# BiForexV3 — інструкція користувача

Усі команди запускаються з папки проєкту `D:\PythonProjects\BiForexV3` у PowerShell.

---

## 1. Щоденна робота бота

### Запуск

```powershell
cd D:\PythonProjects\BiForexV3
.venv\Scripts\python scripts\run_bot.py --live
```

- Вікно терміналу має лишатися **відкритим**, ПК — **увімкненим і з інтернетом**.
- Бот не дає Windows заснути, але вимкнення живлення чи перезавантаження його зупиняють.
- Відкриті позиції **захищені і без бота**: стоп і тейк стоять на біржі.

### Коли бот приймає рішення

Після закриття кожної 4-годинної свічки, через ~20 с. За київським часом (UTC+3):

**03:00 · 07:00 · 11:00 · 15:00 · 19:00 · 23:00**

Між цими моментами бот кожні 30 с звіряється з біржею, але нічого не пише в лог,
поки не відбувається подій (виконання ордера, закриття угоди). Це нормально — він не завис.

### Перевірити стан

В **іншому** вікні терміналу:

```powershell
.venv\Scripts\python scripts\bot_status.py
```

Показує: капітал, позиції, стопи й тейки на біржі, останні сигнали, журнал угод і
загальний PnL.

Лог бота: `logs\biforex.log` (можна відкрити в редакторі).

### Зупинити

| Що потрібно | Як |
|---|---|
| Заборонити **нові** входи, відкриті позиції хай закриваються самі | Створити порожній файл `STOP` у корені проєкту: `New-Item STOP` |
| Дозволити входи знову | Видалити файл: `Remove-Item STOP` |
| Зупинити бота повністю | `Ctrl+C` у вікні бота (стоп і тейк на біржі лишаються) |
| Закрити все вручну | На сайті Binance → Futures → закрити позицію й скасувати ордери (і стоп в "Algo"/"TP/SL") |

### Після перезавантаження ПК

Просто запустіть бота знову (команда з «Запуск»). Він:
- знайде свої відкриті позиції й перевірить, що стоп і тейк на місці;
- пропустить входи по свічці, яка закрилась більш ніж 15 хвилин тому;
- далі працюватиме як звичайно.

Два екземпляри бота одночасно запустити не вийде — другий відмовиться стартувати.

### Telegram-сповіщення

Бот пише в Telegram лише важливе: **закриті угоди** (PnL, капітал), **помилки** (стоп не
поставлено, ордер відхилено, збої зв'язку — не частіше разу на годину + «відновлено»),
**зупинки** (денний ліміт, просадка) і **запуск бота**.

Підключення (один раз):
1. Telegram → **@BotFather** → `/newbot` → назва і username (закінчується на `bot`) → токен.
2. У `config\.env` додати рядок `TELEGRAM_BOT_TOKEN=<токен>`.
3. Відкрити свого бота в Telegram і натиснути **Start**.
4. `.venv\Scripts\python scripts\telegram_setup.py` — знайде ваш chat_id, запише в `.env`,
   надішле тестове повідомлення.
5. Перезапустити бота (`Ctrl+C` і знову `run_bot.py --live`). У лозі: `telegram notifications: on`.

**Чи бот працює** — напишіть боту в Telegram:

| Команда | Відповідь |
|---|---|
| `/status` | «🟢 Бот працює», капітал, позиції зі стопом і тейком, наступне рішення, остання оцінка |
| `/report` | Те саме + угоди за 24 год і загальний PnL |
| `/help` | Список команд |

Бот відповідає протягом ~30 с і лише на ваш chat_id. **Немає відповіді — бот не працює**
(ПК вимкнений, немає інтернету або бота зупинено).

Щодня о **09:00** (за Києвом, взимку о 08:00) приходить **щоденний звіт**. Якщо звіт не
прийшов — перевірте ПК. При зупинці через `Ctrl+C` приходить «⏹ Бота зупинено».

Вимкнути — прибрати `TELEGRAM_BOT_TOKEN` з `.env` і перезапустити бота. Якщо Telegram
недоступний, торгівля від цього не страждає.

## 2. Правила торгівлі (коротко)

- Пари: **BTCUSDT, ETHUSDT**, таймфрейм **4h**.
- Рішення приймає **ансамбль стратегій**: кожна дає оцінку від −1 (вниз) до +1 (вгору),
  підсумок — зважене середнє. Зараз одна стратегія `lgbm_tb` (LightGBM).
- Сигнал: підсумкова оцінка ≥ **+0.10** — лонг, ≤ **−0.10** — шорт (`ensemble.enter_score`).
  Для `lgbm_tb` 0.10 означає «ймовірність напрямку ≥ 0.40 і вона переважає».
- Вхід: **лімітний ордер** на 0.1 ATR кращий за ціну закриття, живе одну свічку (4 год).
- Після виконання: **стоп** = 1 ATR, **тейк** = 2 ATR від ціни входу.
- Вихід також: через **12 свічок** (2 дні) або при сильному протилежному сигналі.
- Одна позиція на пару.

### Ризик на невеликому рахунку

- Біржа має мінімальні розміри: BTC 0.001 (~83 USDT), ETH — від 20 USDT.
  Тому ризик на угоду більший за «1 %»: **BTC ≈ 4–4.5 %**, **ETH ≈ 1.4 %** рахунку.
- Угода пропускається, якщо мінімальний ордер ризикує > 5 % або загальне плече > 5x.
  На рахунку приблизно до 21 USDT **BTC і ETH одночасно не відкриються** (разом > 5x).
- Бектест 04.2023–09.2026 з мінімальними ордерами: капітал ×3, але **просадки до −28 %**.
  Минулі результати не гарантують майбутніх.

### Автоматичні обмеження

| Обмеження | Значення | Що відбувається |
|---|---|---|
| Денний збиток | 6 % | Нових входів немає до кінця доби (UTC) |
| Просадка від максимуму | 30 % | Нові входи **зупинено назавжди**, доки ви не скинете |
| Файл `STOP` | — | Нових входів немає |

Скинути зупинку за просадкою (лише якщо свідомо вирішили продовжувати):

```powershell
.venv\Scripts\python scripts\bot_status.py --reset-halt
```

## 3. Налаштування — `config\config.yaml`

Після зміни конфігу бота потрібно **перезапустити**.

| Параметр | Зараз | Значення |
|---|---|---|
| `execution.testnet` | `false` | `false` — реальний рахунок (з `--live`), `true` — demo |
| `ensemble.enter_score` | 0.10 | Поріг входу за підсумковою оцінкою. Вище — менше угод |
| `ensemble.exit_score` | 0.10 | Протилежна оцінка, що закриває позицію |
| `strategies.<назва>.enabled` | lgbm_tb: true | Чи бере стратегія участь у рішенні |
| `strategies.<назва>.weight` | 1.0 | Вага стратегії в підсумковій оцінці |
| `risk.per_trade_pct` | 1.0 | Бажаний ризик на угоду, % капіталу |
| `risk.max_trade_risk_pct` | 5.0 | Максимум, якщо мінімальний ордер змушує ризикувати більше |
| `risk.max_leverage` | 5 | Загальний обсяг позицій / капітал |
| `risk.daily_loss_pct` | 6.0 | Денний ліміт збитку |
| `risk.max_dd_pct` | 30.0 | Зупинка при просадці |
| `execution.exchange_leverage` | 10 | Плече на біржі (лише скільки маржі блокується) |

Не змінюйте параметри моделей (`label`, `model`, `features`, `timeframe`) без перенавчання —
моделі навчені саме на них. Вмикати / вимикати стратегії й міняти ваги можна без
перенавчання (перед цим перевірте бектестом, див. розділ 7).

### Demo-рахунок (перевірка без ризику)

1. У `config\config.yaml` поставити `testnet: true`.
2. Запустити без `--live`: `.venv\Scripts\python scripts\run_bot.py`

Demo і реальний бот мають окремі журнали: `data\bot\demo.sqlite` і `data\bot\live.sqlite`.

## 4. Ключі API і безпека

- Ключі лежать у `config\.env` (не потрапляє в git). Нікому не пересилайте цей файл.
- Ключ основного акаунта має **обмеження за IP** (IP вашого ПК).
  **Якщо провайдер змінить IP**, бот отримає помилку `-2015 Invalid API-key, IP, or permissions`.
  Що робити: дізнатися новий IP (https://api.ipify.org) → Binance → API Management →
  Edit restrictions → додати IP → перезапустити бота.
- Дозволи ключа: достатньо **Reading + Futures**. **Withdrawals — вимкнено**.
- Demo-ключі: `BINANCE_TESTNET_API_KEY/SECRET`, створюються на demo.binance.com.

## 5. Оновлення моделі (раз на місяць або рідше)

Модель навчена на даних до 26.09.2026. Перенавчати не частіше ніж раз на місяць:

```powershell
# 1. зупинити бота (Ctrl+C) — позиції лишаються захищеними на біржі
.venv\Scripts\python scripts\download_history.py      # дозавантажити історію (кілька хвилин)
.venv\Scripts\python scripts\build_features.py        # ознаки
.venv\Scripts\python scripts\build_labels.py          # мітки
.venv\Scripts\python scripts\train.py                 # перевірка + нові моделі ввімкнених стратегій
.venv\Scripts\python scripts\backtest.py --equity 20 --exchange-limits   # як би торгувала
# 2. запустити бота знову
```

`train.py` друкує якість по роках: рядок `total` у стовпці `improvement_pct` має бути
**додатним** (зараз ≈ +1.3 %). Якщо став від'ємним — нову модель не використовувати
(див. нижче, як повернути попередню).

Моделі зберігаються в `models\<стратегія>\<дата_час>\` (зараз `models\lgbm_tb\`),
активна вказана в `models\<стратегія>\current.json`. Повернути попередню: відредагувати `current.json`, вписавши
назву потрібної папки, і перезапустити бота.

## 6. Якщо щось пішло не так

| Симптом | Причина / що робити |
|---|---|
| `--live given but execution.testnet is true` | У конфігу `testnet: true` — поставити `false` або запускати без `--live` (demo) |
| `execution.testnet is false ... add --live` | Реальний рахунок потребує `--live` |
| `another bot instance holds ...lock` | Бот уже запущений в іншому вікні |
| `-2015 Invalid API-key, IP, or permissions` | Змінився IP або дозволи ключа (розділ 4) |
| `-2019 Margin is insufficient` | Мало коштів на ф'ючерсному рахунку для мінімального ордера |
| `... signal skipped: minimum size risks X% > 5%` | Нормально: мінімальний ордер BTC зараз занадто ризикований для рахунку |
| `... leverage X > 5x at minimum size` | Нормально: вже відкрита інша позиція, дві разом не влазять |
| `no features for bar ...` | Не завантажились дані (інтернет/біржа); бот спробує на наступній свічці |
| `cannot place stop ... closing position at market` | Біржа відхилила стоп — бот закрив позицію для безпеки; перевірити лог |
| `new entries halted` | Спрацювала зупинка за просадкою (розділ 2) |
| Лог давно нічого не пише | Нормально між свічками; перевірити `bot_status.py` |

## 7. Корисні команди для аналізу

```powershell
.venv\Scripts\python scripts\bot_status.py --signals 30     # більше історії сигналів
.venv\Scripts\python scripts\backtest.py                     # бектест на 5000 USDT
.venv\Scripts\python scripts\backtest.py --equity 20 --exchange-limits
.venv\Scripts\python scripts\backtest.py --strategies lgbm_tb --weights 1   # обрані стратегії
.venv\Scripts\python -m pytest                               # тести проєкту
```

Звіти стратегій: `reports\<стратегія>\`, бектести ансамблю: `reports\ensemble\`.
Технічний опис проєкту: `README.md`.
